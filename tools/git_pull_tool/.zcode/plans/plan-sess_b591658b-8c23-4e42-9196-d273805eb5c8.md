# 自动化 Git 代码拉取工具 — 二次修订计划

## 针对最新反馈的补充调整
之前约定“工作区有未提交改动时跳过并报错”，现根据你的新需求调整为：
- **不再预先检查工作区是否干净**。
- 直接执行切分支 + 拉取。
- **只有在真正发生代码冲突（合并冲突 / 切换分支时本地文件会被覆盖）导致 git 命令失败时，才跳过该仓库并记录日志**。
- 对于不影响拉取的新增/修改文件，任由 Git 自动合并或忽略，工具不干预。

## 已确认的其他约束
1. **Windows 10 兼容**：路径使用 `pathlib.Path` 处理，支持 `/` 与 `\`。
2. **Python 3.8 兼容**：仅使用标准库，避免 3.9/3.10+ 语法和 API。
3. **分支后缀处理**：`feature_2609_A_gray` 等只取 `feature_YYMM_X` 前缀参与比较；切分支时优先使用完全匹配前缀的分支，没有则使用带后缀的变体。
4. **配置初始化**：支持 `--init-txt repos.txt` 把每行路径转成 `config.json`，也支持 `--scan <dir>` 自动扫描。
5. **默认并发数 5**，可在配置中修改。
6. **定时任务**：仅提供手动脚本 + Windows 任务计划程序说明，不自动安装。

## 配置设计（config.json）
```json
{
  "concurrency": 5,
  "remote": "origin",
  "branch_pattern": "^feature_(\\d{2})(\\d{2})_([A-Z])",
  "repos": [
    { "path": "C:/work/repo1" },
    { "path": "C:/work/repo2", "branch": "feature_2609_A" }
  ]
}
```

## 核心实现

### 1. 配置读取与生成
- 默认读取 `config.json`，可 `--config <path>` 覆盖。
- `--init-txt <txt>`：把 txt 中每行一个仓库路径转成 `config.json` 模板（忽略空行和以 `#` 开头的注释）。
- `--scan <dir>`：递归查找 `.git` 目录并生成仓库列表。
- 生成配置时统一输出 POSIX 风格路径，避免 Windows 反斜杠转义问题。

### 2. 最新分支自动识别
1. `git fetch --all`。
2. 列出远程分支，使用正则 `^feature_(\d{2})(\d{2})_([A-Z])` 匹配。
3. 提取 **基础分支名** `feature_YYMM_X`，忽略 `_gray` 等后续后缀。
4. 比较规则：
   - 年月越大越新（整数比较，如 `2610 > 2609`）。
   - 同一年月后缀字母越大越新（`A < B < C < D`）。
5. 确定最终远程分支名：
   - 优先使用 `origin/feature_YYMM_X`。
   - 若不存在，使用匹配该基础名的第一个远程分支（如 `origin/feature_2609_A_gray`）。
6. 无匹配分支则记录失败并跳过。

### 3. 单个仓库拉取流程（不再预先检查脏工作区）
1. 确定目标分支：配置分支 或 自动识别的最新分支。
2. 执行 `git checkout -B <branch> <remote>/<branch>`（本地无分支则创建并跟踪）。
3. 执行 `git pull <remote> <branch>`。
4. 捕获命令退出码与 stderr：
   - 成功：记录成功。
   - 失败且 stderr 出现冲突/覆盖类关键字（如 `merge.*conflict`、`would be overwritten by checkout`、`Automatic merge failed`、`CONFLICT`）：记录为“冲突失败”并跳过。
   - 其他失败（网络、权限等）：记录为“失败”并跳过。
5. **不自动 stash、不自动 reset、不清理冲突文件**，保留现场供用户手动处理。

### 4. 并发执行
- 使用 `concurrent.futures.ThreadPoolExecutor(max_workers=concurrency)`。
- 单个仓库失败不影响其他仓库。
- 运行结束后输出汇总：总数、成功数、失败数、冲突失败数及清单。

### 5. 日志与输出
- 控制台实时打印进度。
- 日志写入 `logs/git_pull_YYYYMMDD_HHMMSS.log`。
- 失败信息醒目标注。

### 6. 命令行支持
```bash
python git_pull.py
python git_pull.py --config my_config.json
python git_pull.py --dry-run
python git_pull.py --init-txt repos.txt --output config.json
python git_pull.py --scan C:/work --output config.json
```

README.md 提供 Windows 10 任务计划程序配置步骤与批处理示例，不自动安装。

## 技术栈
- Python 3.8+，仅使用标准库：`json`、`re`、`subprocess`、`concurrent.futures`、`pathlib`、`argparse`、`logging`、`datetime`。

## 风险与回退
- 路径非法 / 非 Git 仓库：提前校验报错。
- 本地新增/修改文件不影响拉取：工具不干预。
- 真正冲突：命令失败，跳过并记录，保留现场。
- 网络失败：不影响其他仓库。
- 远程名非 `origin`：可在配置中全局或按仓库指定。
